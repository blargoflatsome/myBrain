# Decisions

Significant decisions and changes of mind, with the reason, newest at the bottom. Moved out of `docs/SPEC.md` §14 on 2026-11-10 to keep session start-up reading small. Add new decisions at the end of this file.

- 2026-11-06 — Scheduler: Supabase Cron instead of a Netlify scheduled function. A Netlify function every minute is ~43,000 runs a month (roughly 120 of the 300 monthly credits at 10 credits per GB-hour); Supabase Cron is free and checks inside the database. User approved.
- 2026-11-06 — Priority habits added (user's request): a habit can be Priority and gets the full-screen reminder and slider. Standalone priority tasks remain. A due priority reminder offers slide to complete, Snooze (10 min) or Cancel, and does not re-send on its own. Claude's call: priority tasks are one-off or repeat on chosen weekdays.

- 2026-11-06 — Routines (user's choices): chosen weekdays like habits; completed overall = reached the last step even with skips; unstarted scheduled days count as possible. Claude's calls: today counts as possible only once finished; a run can be continued later the same day; removed steps keep their history; one run per routine per day and one log per step per run, with fixed ids so two devices never collide.

- 2026-11-06 — Wording changed by the user (commit "message tweaks"): Habits line "You are only in competition with yourself.", Tasks page heading "Tasks" with "Let's get these To-Done.", Quests intro "Bored? We have a quest for that.", inbox empty state "Past you hasn't left anything to sort." Tests and spec follow the user's wording.

- 2026-11-06 — Bug fix (user report): a habit created after its timer window was logged as missed immediately. The creation day is now due by midnight, and a "missed" log whose day is still open is removed automatically.

- 2026-11-06 — Habits (user's choices): the timer starts at the notify time; habits repeat on chosen weekdays; streak visibility defaults to only me and is editable now. Claude's calls: no timer means due by midnight; a completion can be undone until the deadline; misses are written to `habit_logs` when the app notices a deadline passed (the server job in step 7 will also do it); cached streaks on `habits` are recalculated from `habit_logs`. Other users can only read streaks through `shared_streaks()` (a function since step 7; Supabase flags owner-rights views), which hides private habits and anyone not set to everyone ("people I approve" waits for Phase 2 approvals).
- 2026-11-06 — Navigation is a text-only menu on the left (Tasks, Habits, Quests, Inbox, Profile), user's request; it replaced a short-lived bottom bar with icons. Always shown from tablet width up (laptop, Pi display); on a phone a Menu button slides it out from the left (Claude's call, as the user didn't choose).

- 2026-11-06 — Energy levels changed (user's request): Meh removed, **Fun** added between Ugh and Needs setup; new quests default to **Ugh**. Quests that were Meh (the old lowest level) became Ugh (the new lowest).

- 2026-11-06 — Added energy level **Needs setup**, ranked between Ugh and Medicated (user's choice).

- 2026-11-06 — Capture is type-first (user's request): pick Task, The Vault, Quest or Decide later, then a form made for that type; only the title is required. New quests default to Meh / 30 min everywhere. The Quests page no longer has its own Add box. Quests saved before this keep no time/energy and still match any filter.

- 2026-11-06 — Random Quest: energy Meh < Ugh < Medicated, time buckets 30 min / 2 hours / Half a day / A full day, recent = last 3 picks (user's choices). Untagged quests match any filter so captured quests still come up (Claude's call; easy to change). Quest wording drafted by Claude in the established voice.

- 2026-11-06 — Incident: the step 2 capture migration had not been applied to prod when step 2 merged, so captures on the live site could not upload, and the sync queue stopped retrying them. Fixed by applying the migration to prod and retrying refused changes on every sync (§7). From now on Claude applies migrations to prod itself right before merging and confirms with `supabase db push`.

- 2026-11-06 — Task priorities: Low green, Medium yellow, High red, shown as a dot and label; default Low; red title text only for carry-over. Carry-over wording drafted by Claude at the user's request (in `src/messages.ts`). Today = date in the device's current timezone; carry-over count = whole calendar days from due date to today, computed on display.

- 2026-11-06 — Step 2 build details: Quest and Decide later save in one tap after typing; Task asks for the optional date, then Save; The Vault saves when a bucket is tapped. The whole captured text becomes the item's title (inbox: body). Filing an inbox item is a conversion: the new item is created and the inbox row is soft-deleted. Convert buttons on tasks, vault items and quests arrive with those screens (steps 3, 4, 8). Each user's on-device data lives in its own IndexedDB store and is kept on sign-out so unsynced captures are never lost.

Starter Vault buckets: Shopping list, Restaurant reviews, Places to go. Chrome speech recognition accepted despite audio going to Google.

- 2026-11-06 — Sync layer: custom Dexie queue instead of RxDB or PowerSync (reasons in §7). Conflict rule clarified: last edit to reach the server wins, because device clocks are not trusted; accepted for Phase 1 as a single user.

- 2026-11-06 — Step 1 schema covers the shared conventions (server-set `created_at`/`updated_at` trigger, soft delete, RLS pattern) and `profiles`, created automatically on first Google sign-in. Each later feature's tables are added in that feature's build step, following the same pattern. Clients never hard-delete; account deletion will be a server function.
- 2026-11-06 — Docker is not installed, so there is no local Supabase stack. Database rules (RLS) are tested against the dev project two ways: Vitest integration tests as a signed-out visitor (`tests/integration`, skipped in CI where no keys are configured), and SQL rule checks that act as two fake users inside one rolled-back statement (`supabase/tests/*.sql`, run with `npm run test:db`; pgTAP's `supabase test db` needs Docker). Each check raises to force the rollback, so `scripts/test-db.mjs` reads the raised `PASS:`/`FAIL:` message and reports a normal pass or fail. Migrations go to dev with `npx supabase db push --remote`.
